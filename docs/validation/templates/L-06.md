## Method

From each take's events (`GET /api/v1/training/sessions/{id}/events`): for every `rep_completed`
event, latency = event `t_us` − `data.repetition.t_end_us` (session clock; the engine part). The
segmenter must see activity below `end_below` for `end_hold_ms` (150 ms default) before it ends a
repetition, so about 150 ms is expected. The client part (event → cue visible) is measured as in
L-03 with the phone filming the athlete's last movement and the cue banner.
